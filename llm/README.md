# ローカル LLM（`llm/`）

この PC の GPU（RTX 3050 Laptop 4GB）で小さいオープンウェイトのモデルを動かし、どのリポのセッションからも Bash で呼べるようにした物（2026-10-14）。

- 道具: `llm.py`（標準ライブラリだけ）。本人の端末からは `llm`（`powershell/profile.ps1`）。
- 中身: llama.cpp の `llama-server`（CUDA 12.4 版・b11617）＋ **Qwen3.5-2B（Q8_0）**。取りこぼしが困る当たり付けだけ Qwen3.5-4B（UD-IQ3_XXS）も選べる。どちらも Apache 2.0。
- 置き場: `%LOCALAPPDATA%\llm`（`bin`・`models`・`server.log`・`usage.jsonl`・`api-key.txt`）。リポの外。落とし直せる物だけなので控えは要らない。

## 何に使うか

| ねらい | 向き | 使い方 |
|---|---|---|
| トークン代（プランの使用量）を減らす | △ | 長い文字起こし・ログ・JSON を Claude に丸ごと読ませる前に、要点や該当箇所だけ抜かせる。効くのは長い物を読む日だけ（使用量の大半は同じ文脈の読み直しで、ここでは減らない）。`usage.jsonl` で量を測って判断する |
| 簡単な作業 | ○ | 下読みの要約・抜き出し・迷惑メールの候補分け・字幕の言いよどみ削り |
| セッションをまたいだ確かめ | × | 小さいモデルは見落としと空騒ぎが多い。機械的な照合はスクリプト、別の目は `agy` |
| 機密の物を扱う | ○ | 外へ出ない。`-o` で答えをファイルにだけ書けば、Claude は中身を見ずに済む。本人が自分の端末で `llm` を直に使ってもよい |

### 任せない物

- 計算・数字の断定・事実の断定（ニュースなど）
- 公開する言葉の確定（キャプション・字幕の最終版）、本人の言葉の要約を本人の言葉として使うこと
- privacy・公開の可否の最終判断（**当たり付けまで**。取りこぼしはあると思って、最後は人か Claude が原文で確かめる）
- 鍵・トークン・`.env`・他人の名前が並ぶ名簿は入れない。画像と動画は入らない（文字だけ）

## 作業別の呼び方（各リポのセッションに取ったアンケートの答えから）

**トークンが減るのは、Claude が材料を読まずに、パスだけを渡した時だけ**。先に Read で全部読んでから llm に渡すと、かえって増える。答え（短い）だけを読み、要る所だけ原文の該当行を開く。

| 作業 | 呼び方の例 | 答えの扱い |
|---|---|---|
| 動画の書き起こしから、公開前に確かめる所の当たり付け（人名・時刻・大会名・ジム名・勤務の話） | `--model 4b "公開前に確かめる箇所を、人名・時刻・大会名・ジム名・勤務の話に分けて JSON の配列で。原文の字をそのまま" -f 書き起こし.txt --json` | **取りこぼしがある前提**。時刻・人名は正規表現でも拾って突き合わせる。可否の判断は Claude と本人 |
| 長い文字起こし・記録の下読みと要約 | `"5行で要約。書いていないことは書かない。最後に、詳しく読むべき箇所を最初の数語で3つ" -f 記録.txt` | 要約は道しるべ。引用・数字は原文で確かめてから使う |
| 長い JSON（計測の台帳・insights など）から条件に合う物を探す | `"caption に「〇〇」を含む投稿の id を全部、カンマ区切りで" -f data.json` | id が返ったら、その id だけを原文から読む。合計・平均などの計算はスクリプトで |
| 長い実行記録・ログ（検査の道具・psql・ビルド）の下読み | `"失敗・警告の行と、その直前の原因らしき行だけを抜き出して。無ければ『なし』" -f run.log` | 先に grep で絞れる物は grep。LLM は形の決まっていない記録だけ |
| 長い手順書・冊子から該当の節を探す | `"〇〇の手順が書いてある節の見出しを3つまで" -f manual.md` | 見出しが分かったら、その節だけを開く |
| 迷惑メールの候補分け | `"迷惑メール（詐欺・フィッシング）の候補の番号を {\"迷惑\": [...]} で" -f mails.txt --json` | 候補まで。消す・迷惑メールにするのは決まりどおり本人 |
| 字幕の言いよどみ・言い直しを削った下書き | `"言いよどみと言い直しの繰り返しを削る。意味を変えない・言葉を足さない。直した文だけ" -f caption.txt` | 下書き。字幕の確定は Claude と本人 |
| 面談・家計など機密の物の要約 | `"要点を5行で" -f 面談.txt -o 要約.txt` | `-o` ならClaude の画面にもログにも中身が出ない。本人が自分の端末で `llm` を直に使ってもよい |
| 店名の分類 | `"次の10個から1つだけ（組み合わせない）…例: …" -f 表に無い店名.txt` | **苦手**（16 件中 12〜13）。店名→分類の表を手元に持ち、表に無い物だけ聞く |

使わない方がよい物: 短い物（Claude が読んでも安い）・計算・コードの修正・別の目としての確かめ（見落としと空騒ぎが多い＝別の目は `agy`）。

## 使い方

```bash
L=C:/Users/81809/Documents/Repositories/setup-neovim-wezterm/llm/llm.py
python $L "3行で要約して。書いていないことは書かない" -f talk.txt
python $L "人名・時刻・大会名を JSON の配列で抜き出して。原文の字をそのまま" -f talk.txt --json
python $L "迷惑メールの候補の番号を {\"迷惑\": [...]} で" -f mails.txt --json -o result.json   # 画面には件数だけ
python $L --model 4b "公開前に確かめる箇所を全部" -f talk.txt   # 取りこぼしを減らしたい時（遅い）
python $L --status    # 動いているか・どのモデルか・メモリ・VRAM
python $L --stop
```

- 材料は `-f`（何個でも・`-` は標準入力・UTF-8）。指示は短く、材料と分ける。
- 分類は「次の 10 個から 1 つだけ（組み合わせない）」と選択肢を書き、例を 3〜5 個添える（書かないと選択肢をつなげた答えを返す）。
- 文脈の上限は 32K トークン（日本語で約 3〜4 万字）。超えると終了コード 3 で止まる＝分けて渡す。
- 1 個のサーバーをみんなで使う。同時に呼ぶと順番待ちになる。
- 終了コード: 0 成功／2 使い方の誤り／3 VRAM が足りない・入力が長すぎる／4 サーバーが立たない・応答の誤り。
- `usage.jsonl` には時刻・呼んだフォルダ・トークン数・秒数だけを残す（中身は残さない）。

## しくみ

1. 呼ぶと、見張り役（`llm.py --serve`）が裏で `llama-server` を立てる。窓は出ない。初回は 10〜30 秒、2 回目からは数秒で答える。
2. 5 分使われないと、サーバーがモデルを GPU から降ろして眠り、見張り役がサーバーごと終わらせる＝**使っていない時はメモリも VRAM も食わない**。次に呼ばれたらまた立つ。
3. 待ち受けは `127.0.0.1` だけ。合言葉（`api-key.txt`・初回に自動で作る）が無い呼び出しは断る。CORS は localhost だけ、処理中の中身が見える窓口（`/slots`）と画面（Web UI）は切ってある＝ブラウザのページから勝手に使われたり、中身を覗かれたりしない。
4. VRAM の空きが足りない時は立てない（終了コード 3）。一部を CPU に回すと、RAM を食って 20 倍遅くなるため（下の実測）。

### メモリへの影響（2026-10-14 実測・Qwen3.5-2B）

| 状態 | プロセスの Private | VRAM | 備考 |
|---|---|---|---|
| 止まっている（ふだん） | 0 | 0 | 5 分使わなければこの状態に戻る |
| 答えている間 | 約 3.0GB | 約 2.3GB | Private の大半は、Windows が GPU のメモリの分をコミットとして数える物。llama.cpp が RAM 側に持つのは読み込み口の 0.5GB（mmap）だけ |
| 眠った直後 | 約 0.44GB | 約 0.1GB | 見張り役が 10 秒以内に終わらせる |

- llama-server の既定では、プロンプトの控えを **RAM に最大 8GiB** 溜める（`--cache-ram`）。`-cram 0` で切ってある。
- `--no-mmap`（今の `-lm none`）は付けない。CPU 側の表を RAM に確保するので逆に増える。

## モデルの選び方（2026-10-14 実測）

条件は「**VRAM（空き約 3.0GB）に全部載ること**」。載らない物は一部が CPU に回り、RAM が足りないこの PC では書き出しが毎秒 1.7 トークンまで落ちた（Qwen3.5-4B Q4_K_M・`-c 32768`。ベンチでは毎秒 32）。Qwen3.5-4B Q4_K_M（32 層中 27 層まで）と Gemma 4 E4B（43 層中 35 層まで）はここで外れた。

載る 3 つを、各リポのセッションに取ったアンケートの作業に似せた架空の材料で比べた（CUDA 版・`-c 32768`・KV q8_0・温度 0.2・考える過程なし）。

| 作業 | Gemma 4 E2B Q4_K_M | **Qwen3.5-2B Q8_0** | Qwen3.5-4B UD-IQ3_XXS |
|---|---|---|---|
| 書き起こしから人名・時刻・大会名・ジム名を抜く（10 件） | 5（時刻は 0/4） | 8 | 10（種類の取り違え 2） |
| 長い JSON（19K トークン）から該当 6 件を探す | 4＋誤り 8 | **6・誤りなし** | 5・誤りなし |
| 店名の分類（16 件） | 13 | 9（例を足して 12） | 例を足して 13（1 行落とし） |
| 迷惑メールの候補（6 通） | 6 | 6 | 6 |
| 字幕の言いよどみ削り | ○ | ○ | ○ |
| 3 行の要約 | ○ | △（細部に誤り） | ○ |
| 書き出しの速さ（トークン/秒） | 28 | 30〜34 | 15〜20 |
| 読み込みの速さ（トークン/秒） | 600〜1150 | 700〜1870 | 260〜770 |
| VRAM（使う分） | 1.7GB | 2.3GB | 2.7GB（残り 0.4GB） |
| 答えている間の Private | 2.3〜2.6GB | 3.0GB | 3.4〜3.7GB |

- **既定は Qwen3.5-2B**: 長い物から探す・抜き出すが確かで、速く、VRAM に 1GB ほど余る。
- **4B は `--model 4b` で**: 当たり付けの取りこぼしが一番少ない。ただし速さは半分で、VRAM の残りが 0.4GB＝ブラウザで動画などを開いていると立たない。
- Gemma 4 E2B は分類が一番よかったが、抜き出しで時刻を全部落とし、長い JSON で誤りが多かった。公開の日本語の評価（指示に従う力）では E2B が上という調べもあるので、モデルが新しくなったら同じ材料で測り直す。
- **店名の分類はどれも苦手**（店の知識が足りない）。月 1 回の家計の分類は、店名→分類の表を手元に持ち、表に無い物だけ聞くか、Claude に任せる。
- llama.cpp は CUDA 版が Vulkan 版より大きく速かった（Qwen3.5-4B・全部 GPU: 読み込み 860 対 114・書き出し 32 対 6.4 トークン/秒）。winget の `ggml.llamacpp` は Vulkan 版なので使わない。CUDA 13.x 版はドライバ R580 以上が要る（この PC は R576）。

## 入れ方・戻し方（PC を作り直した時も）

前提: NVIDIA のドライバ（R576 以上）と Python。

```bash
python llm/llm.py --install              # llama.cpp（b11617・CUDA 12.4）と Qwen3.5-2B を落とし、チェックサムを確かめる
python llm/llm.py --install --model 4b   # 4B も使うなら
python llm/llm.py --self-test
python llm/llm.py "こんにちは"
```

- 入れ直しても、そろっていれば落とさない（「ある」と出る）。
- 版を上げる時は、`llm.py` の `LLAMA_BUILD` と `LLAMA_ZIPS` のチェックサム（GitHub の Releases の各ファイルの `sha256`）を書き換えて `--install`。モデルを替える時は `MODELS_TABLE` を書き換え、上の比べ方で測ってから。
- 消す時: `python llm/llm.py --stop` → `%LOCALAPPDATA%\llm` を消す → `powershell/profile.ps1` の `llm` 関数を消す。設定・常駐タスク・MCP・PATH には何も足していない。

| 答えが極端に遅い（毎秒数トークン） | `--force` で立てていないか。VRAM が足りずに CPU に回っている。`--stop` して空けてから |

| `--model 4b` なのに 2b で答えた | 先に 2b で立っていた（画面に一言出る）。使い終わって 5 分待つか `--stop` してから |
