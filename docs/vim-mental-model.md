# Vim 思考モデル — 「なぜそう動くか」

キーの丸暗記をやめるための 1 本。**Vim は言語**で、文法を 1 つ理解すると未知の操作が自力で組める。
キー早見は `docs/keybinds.md`。本書は**仕組み**だけ。

---

## 結論: Vim は「動詞 + 名詞」の言語

VSCode は「操作 1 つ = ショートカット 1 つ」の暗記ゲーム。
Vim は **動詞（何をする）+ 名詞（どこに）** の**組み合わせ**。掛け算なので、覚える数が激減する。

```
  [回数]  動詞      名詞
   3      d         w      → 3 単語削除
          c         i"     → クォート内側を書き直し
          y         $      → 行末までコピー
          d         2j     → カーソル行＋下 2 行を削除
```

動詞 5 個 × 名詞 15 個 = **75 通りの操作が 20 個の暗記で出せる**。これが Vim の効率の正体。

---

## 1. 動詞（オペレータ）— 何をするか

| 動詞 | 意味 |
|---|---|
| `d` | delete（削除・カット） |
| `c` | change（削除して入力モードへ） |
| `y` | yank（コピー） |
| `>` / `<` | インデント 右 / 左 |
| `=` | 自動整形 |
| `gc` | コメントトグル |

**ルール**: 動詞を 2 回打つ（`dd` `yy` `cc` `>>`）= **その行全体**に適用。

---

## 2. 名詞 — どこに効かせるか（2 種類ある）

### A. モーション（カーソルの移動先まで）

「ここから “その場所” まで」を範囲にする。

| モーション | 範囲 |
|---|---|
| `w` / `b` | 次 / 前の単語まで |
| `$` / `0` | 行末 / 行頭まで |
| `gg` / `G` | ファイル先頭 / 末尾まで |
| `}` / `{` | 次 / 前の段落まで |
| `f x` | 行内の次の `x` まで |
| `2j` | 下 2 行まで |

例: `d$` = カーソルから行末まで削除。`yfx` = 次の `x` までコピー。

### B. テキストオブジェクト（意味のカタマリ）★ Vim の真骨頂

カーソルが**中にいれば**、位置を問わずカタマリ全体を掴む。`i`=inside（中身）/ `a`=around（囲い込み）。

| オブジェクト | 範囲 |
|---|---|
| `iw` / `aw` | 単語 / 単語＋空白 |
| `i"` / `a"` | クォート内 / クォート込み |
| `i(` `i{` `i[` | 各カッコの内側 |
| `it` / `at` | HTML/XML タグの内 / タグ込み |
| `ip` / `ap` | 段落 |

**威力の例**: 文字列 `"hello world"` の中ならどこにカーソルがあっても —
- `ci"` → 中身を消して入力（→ `""` の中で待機）
- `da(` → カッコごと丸ごと削除
- `yi{` → 波カッコの中身をコピー

> VSCode で「ダブルクリックで単語選択 → 入力」していた操作が `ciw` の 3 打。**カーソルを単語の先頭に置く必要すらない**（単語の上にいればいい）。これが効率の体感ポイント。

---

## 3. `.`（ドット）= 直前の変更を繰り返す ★ 最重要の 1 キー

`.` は「いま行った編集 1 回分」を丸ごと再実行する。**Vim 使いが手放せない唯一のキー**。

例: 複数箇所の `foo` を `bar` にしたい
1. `ciw` で書き直し → `bar` と入力 → `Esc`（1 回目）
2. 次の `foo` へ移動（`/foo Enter` や `n`）
3. **`.` を押すだけ**で `bar` に置換（2 回目以降）

「移動 → `.`」のリズムで、置換コマンドを書かずに点在修正が片付く。

---

## 4. 回数（count）— 掛け算する

動詞・モーションの前に数字を置くと繰り返す。

| 例 | 意味 |
|---|---|
| `3w` | 3 単語進む |
| `5dd` | 5 行削除 |
| `d3j` | カーソル行＋下 3 行削除 |
| `2ci"` | （※ count は textobj には基本効かない。普通は使わない） |

---

## 5. レジスタ — Vim のクリップボードは複数ある

コピー（`y`）も**削除（`d`）も**「レジスタ」という名前付き棚に入る。VSCode の単一クリップボードと違い**複数ある**。

| レジスタ | 中身 |
|---|---|
| 無名（既定） | 直前に yank / delete したもの → `p` で貼る |
| `"0` | **最後に yank だけ**したもの（削除で上書きされない） |
| `"+` | **OS クリップボード**（Windows と共有） |
| `"a`〜`"z` | 自分で名前を付けて保存（`"ayy` で a に行コピー） |

**よくある罠と回避**:
- `yy` でコピー → `dd` で別行削除 → `p` したら**削除した行**が出てきた
  → 無名レジスタが `dd` で上書きされたため。**yank 専用の `"0` を使う**: `"0p`
- Windows のブラウザ等に貼りたい → `"+y` でコピー（`+` = OS クリップボード）

> LazyVim は OS クリップボード連携を有効化済なので、多くの場面で `y` / `p` がそのまま OS と繋がる。繋がらない時だけ `"+` を明示。

## 6. buffer / window / tab — 混乱する 3 兄弟

VSCode の「タブ」と Vim の「タブ」は**別物**。ここで全員つまずく。

| 概念 | 正体 | VSCode で言うと |
|---|---|---|
| **buffer** | メモリに開いた**ファイルの中身** | 開いているファイル（タブ相当） |
| **window** | buffer を映す**画面の枠**（分割するとできる） | エディタの分割ペイン |
| **tab** | window のレイアウト**一式**を保存したもの | （VSCode に対応物なし・近いのは「ウィンドウ全体の配置」） |

**実用上の理解**:
- 「次のファイルへ」= バッファ切替 → `Shift+L` / `Shift+H`
- 「画面を 2 分割して別ファイルを並べる」= window 分割 → `Space -`（横）/ `Space |`（縦）
- **Vim の tab は当面使わない**。VSCode のタブ感覚は **buffer** が担当する。

> WezTerm にも「タブ」があり、これは**さらに別レイヤー**（ターミナルのタブ）。3 つのタブが登場するので、`docs/keybinds.md` 冒頭のレイヤー図を併読。

## 7. モード = 状態機械

```
        i a o A I O など
   Normal ───────────────▶ Insert
     ▲                       │
     │       Esc / Ctrl+[    │
     └───────────────────────┘
     │
     │ v / V / Ctrl+v
     ▼
   Visual（範囲選択）── d/y/c で動詞を適用 ─▶ Normal
     │
     │ :
     ▼
   Command（: で開始、Enter で実行）
```

- **Normal が母艦**。移動・削除・コピー・コマンド入力はここから。困ったら `Esc` で必ず戻る。
- **Insert は文字を打つ時だけ**の一時状態。長居しない（打ったら `Esc`）のが Vim 流。
- **Visual** は「先に範囲を選んでから動詞」。動詞+名詞が思いつかない時の保険（`viw` で単語選択 → `d` でも `diw` と同じ）。

## 8. 組み合わせ例で文法を体感

| やりたいこと | 組み立て | 思考 |
|---|---|---|
| この単語を消す | `diw` | delete + inside word |
| この単語を打ち直す | `ciw` | change + inside word |
| 関数の引数を全消し | `di(` | delete + inside `(` |
| 行末までコピー | `y$` | yank + 行末まで |
| 下 3 行をインデント | `>3j` or `>4>`… | `>` + 下 3 行 |
| 引用符の中を書き直す | `ci"` | change + inside `"` |
| 段落をまるごと削除 | `dap` | delete + around paragraph |
| カーソル下の単語を全箇所修正 | `ciw`→入力→`Esc`→`n`→`.` | change + dot 繰り返し |

**やり方が分からない操作に出会ったら**: 「動詞は何？名詞は何？」と分解する。だいたい組み合わせで出せる。

---

## まとめ: 最初に体に入れる 3 つ

1. **動詞 + 名詞**（`diw` `ci"` `d$`）— これが Vim の全て
2. **`.`（ドット）** — 直前の編集を繰り返す
3. **buffer = VSCode のタブ**（`Shift+L`/`Shift+H` で切替）、Vim の tab は忘れていい

残りは使いながら `docs/keybinds.md` を引けばいい。文法さえ入れば暗記量は最小。
